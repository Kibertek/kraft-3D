# План админ-панели сайта KRAFT 3D

## Назначение

Закрытая административная часть сайта для управления публичным содержимым без редактирования исходного кода. Админ-панель работает через серверный API; браузер не подключается напрямую к базе данных.

## Разделы

### 1. Обзор
- Новые заявки с сайта и краткая сводка по контенту.
- Состояние синхронизации с KRAFT 3D Manager.
- Предупреждения о сбоях загрузки файлов и API.

### 2. Галерея работ
- Добавление, изменение порядка и скрытие фотографий.
- Название, описание, категория, дата и изображение обложки.
- Возможность позднее подключить импорт публикаций/фотографий из VK через официальный API и с учётом ограничений платформы.
- Удаление или архивирование без поломки страницы.

### 3. Услуги
- Редактирование названий и описаний услуг.
- Управление порядком отображения, публикацией и иллюстрациями.
- Возможность задавать только предварительные цены или диапазоны, если бизнес решит их показывать.

### 4. Тексты и контакты
- Тексты главной страницы, описание компании, контактные ссылки VK и Telegram.
- Редактирование времени работы и кратких объявлений.
- Проверка ссылок перед публикацией.

### 5. Заказы с сайта
- Список заявок, фильтры и поиск.
- Просмотр контактов, описания, прикреплённых файлов и статуса синхронизации.
- Ссылка на запись в KRAFT 3D Manager по общему ID.
- Не создавать второй независимый процесс управления производством: расчёт себестоимости, производство и финансовый учёт остаются в Manager.

### 6. Пользователи и безопасность
- Только авторизованный доступ.
- Роли на будущее: владелец/администратор и редактор контента.
- Смена пароля, завершение сессий и журнал административных действий.
- Защита от перебора паролей, ограничение попыток входа и безопасное восстановление доступа.
- Двухфакторная аутентификация как возможный следующий этап.

### 7. Настройки сайта
- Публичные контакты и ссылки.
- Настройки SEO: заголовки, описания и изображение для предпросмотра ссылок.
- Управление баннерами и сообщениями об обслуживании.
- Не размещать секретные ключи API в интерфейсе или frontend-коде.

## Предлагаемая архитектура

- Frontend сайта: React + TypeScript.
- Административные страницы: защищённый маршрут, например `/admin`.
- Backend: отдельный серверный API с авторизацией и проверкой прав на каждый запрос.
- База данных: PostgreSQL на сервере.
- Медиафайлы и файлы заказов: защищённое хранилище, а не публичные директории с предсказуемыми именами.
- KRAFT 3D Manager синхронизируется с заказами через API и общий уникальный ID.
- Административные изменения контента сохраняются на сервере и публикуются на публичной части сайта.

## Принципы безопасности

- Нельзя считать скрытый маршрут `/admin` защитой сам по себе.
- Нельзя хранить пароли или API-секреты в клиентском коде, репозитории или открытых конфигурационных файлах.
- Сервер обязан проверять авторизацию и права на каждую операцию.
- Использовать HTTPS, безопасные cookie-сессии или проверенный механизм токенов, ограничение частоты запросов, CSRF-защиту при cookie-аутентификации и журналирование.
- Для удаления и массовых изменений предусмотреть подтверждение и возможность восстановления/архивирования.
- Настроить резервное копирование базы, контента и медиафайлов.

## Этапы реализации

1. Согласовать поля контента и структуру пользователей/ролей.
2. Создать backend API, базу PostgreSQL и авторизацию.
3. Создать каркас админ-панели и обзорный экран.
4. Реализовать управление галереей, услугами, текстами и контактами.
5. Подключить список заказов и состояние синхронизации с Manager.
6. Добавить журнал действий, защитные меры, тестирование и резервное восстановление.

## Границы первого релиза

В первой версии достаточно одного владельца-администратора, редактирования галереи, услуг, текстов и контактов. Сложные роли, клиентский кабинет, аналитика и импорт из VK могут быть следующими этапами. До появления backend и авторизации административная панель не должна быть доступна для реального редактирования в публичной сети.
